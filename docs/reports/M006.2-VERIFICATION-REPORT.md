## 1. Executive Summary

Mission M006.2 resolves the security, economic-modeling, and event-evidence review findings identified after M006.1 across CrossGuard's read-only recovery preflight tool (`script/ops/crossguard_healthcheck.py`), test harnesses (`test/ops/test_crossguard_healthcheck.py`, `test/mocks/MockOmniSystemContract.sol`, `test/unit/M006Recovery.t.sol`), and operational/security documentation.

Key remediations delivered under strict ₹0 budget, zero-deployment, zero-live-transaction, and read-only constraints:
1. **Workstream A (P1 — Callback Configuration Drift Protection):** Eliminated a P1 failure mode in which historical `CallbackRequest` recipient evidence could still authorize `RETRY_ELIGIBLE` even after `CrossGuardReactive.destinationCallback()` drifted to a different target. Preflight now validates exact 20-byte EVM addresses (`validate_evm_address()`) and enforces `expected_callback == historical_callback_request_recipient == current_destination_callback` for `RETRY_ELIGIBLE` (and `expected_callback == current_destination_callback` for `DISPATCH_REQUIRED`), failing closed as `RETRY_BLOCKED` (or `RETRY_UNKNOWN`) with explicit `configuration_comparison` diagnostics and zero CLI auto-adoption.
2. **Workstream B (P2 — Reconciled Fee & `_maxChargeGas` Model and Payment Path Separation):** Removed `exceeds_max_charge_gas` (`gas_limit + _extraGas > _maxChargeGas`), which conflated execution fee math with payment-settlement gas limits. Enforced `fee = p_base * (C / 1000) * (g_used + K)` (`p_base = max(gas_price, base_fee)`, uint256 overflow-checked), restricted `_maxChargeGas` strictly to payment-settlement gas checks (`== 0` or `< settlement_gas_requirement`), explicitly flagged effective forwarded gas as unverified (`effective_forwarded_gas_exact = None`), and separated **Reactive System Contract (`REACT`)** automated `react()` warnings (`REACTIVE_PATH_WARNING`, blocked only under `--require-reactive-reserves`) from **Destination Callback Proxy (`ETH`)** hard delivery blockers (`RETRY_BLOCKED`).
3. **Workstream C (Authoritative `CallbackRequest` ABI Validation):** Removed the unverified/mock `CallbackRequestedV1` fallback from preflight receipt acceptance and added `decode_callback_request_data_strict()` enforcing `CallbackVersion.V_1_0` (`version == 0`), valid inner `CallbackConfiguration_V_1_0` bytes (`chainId == 1301`, `recipient`, `gasLimit >= 100_000`, matching non-empty `payload`), and exact 4-topic `CallbackRequest(uint256,address,address,uint8,bytes)` verification. Updated `MockOmniSystemContract.sol` and `RevertableOmniSystemContract` to emit the authoritative `CallbackRequest` event.
4. **Workstream D (Callback Record Validation & Correlation):** Hardened `decode_callback_records()` to reject truncated addresses, negative/out-of-range uint256 values, malformed hex errors, and trailing junk tokens while adding `callback_record_correlation` telemetry acknowledging the 6-field schema's lack of recipient/nonce fields.
5. **Workstream E (Solidity Recovery Invariants):** Preserved all M006.1 state-machine guards (`CrossGuardReactive.sol` bytecode unchanged at `6,689 B` runtime) and added `test17_OnChainConfigDriftTargetsNewCallbackOnRetry` and `test18_WorkstreamEUnauthorizedDispatchAndRetryGuardsRemainStrict` (`169` Foundry tests passing across `12` suites including `256`-run / `128,000`-call `M006RecoveryInvariantTest`; `104` Python tests passing).

## 4. Callback Configuration Drift Protection

1. **Why Historical Evidence Alone Is Unsafe:** As demonstrated in `test17_OnChainConfigDriftTargetsNewCallbackOnRetry`, `CrossGuardReactive.retryFailedCallback(positionId, expectedNonce, reasonCode)` constructs a new `ISystemContract.CallbackConfiguration_V_1_0` using the **current** `destinationCallback` storage slot, NOT the recipient recorded in the earlier transaction receipt.
2. **Enforced Address Invariants:**
   - **Retry Path (`RETRY_ELIGIBLE`):** Strictly enforces:
     $$\text{expected\_callback} == \text{historical\_callback\_request\_recipient} == \text{current\_destination\_callback}$$
     across both indexed `CallbackRequest.recipient` and inner `CallbackConfiguration_V_1_0.recipient`.
   - **Deferred Dispatch Path (`DISPATCH_REQUIRED`):** Strictly enforces:
     $$\text{expected\_callback} == \text{current\_destination\_callback}$$
     (with `historical_callback_request_recipient = None`).
   - **Strict 20-Byte EVM Validation:** `validate_evm_address()` requires exact `0x`-prefixed 40-hex-character addresses (`RETRY_UNKNOWN` on truncated/oversized/non-hex inputs). `expected_callback == 0x0...0` is rejected (`RETRY_BLOCKED`). Case-insensitive normalization (uppercase/lowercase) is supported strictly on valid 40-hex addresses.
3. **Migration Policy:** Recipient drift is never auto-adopted via `--callback-address` overrides (`test_94` proves overriding CLI flags still fails closed because historical != drifted address). Drift sets `status = RETRY_BLOCKED` (`RETRY_UNKNOWN` if historical disagrees while expected == current), populates `configuration_comparison`, sets `safe_to_consider_recovery = False`, and directs the operator to execute an explicitly reviewed configuration migration.

## 6. Callback Record Correlation

- **Official 6-Field Schema Preserved:** `getCallbacks(uint256)((uint256,address,uint256,uint256,uint256,bytes)[])` (`blockNumber`, `reactiveContract`, `callbackIndex`, `destinationChainId`, `destinationTxHash`, `error`).
- **Hardened `decode_callback_records()`:**
  - Enforces exact 6 fields per formatted tuple, strict `0`..`uint256_max` numeric bounds, strict 20-byte `validate_evm_address()` on `reactiveContract` (no silent zfill padding), strict even-length `0x` hex error bytes, and rejects trailing/malformed tokens outside tuple brackets.
  - Empty array `[]` / `0x` -> `RETRY_PENDING` (never proof of failure).
  - Nonzero `destinationTxHash` + empty `error` -> `RETRY_ALREADY_SUCCEEDED` ONLY when `BorrowingController.lastProcessedNonce >= expectedNonce`; if destination nonce is behind, returns `RETRY_UNKNOWN` (contradiction).
  - Zero `destinationTxHash` + empty `error` -> `RETRY_PENDING`; zero `destinationTxHash` + nonempty `error` -> `RETRY_UNKNOWN`.
  - Multiple matching records (`> 1` matching `reactiveContract` & `destinationChainId == 1301`) fail closed as `RETRY_UNKNOWN` without silently selecting one record.
- **Explicit Limitation Reported:** Preflight emits `callback_record_correlation` and records in `missing_or_unavailable_evidence` that the 6-field schema omits recipient address and origin nonce.

## 7. Fee and Max-Charge Model

- **Exact Execution Fee Equation:**
  $$\text{fee\_wei} = \left\lceil \frac{p_{\text{base}} \times C \times (g_{\text{used}} + K)}{1000} \right\rceil$$
  where $p_{\text{base}} = \max(\text{gas\_price}, \text{base\_fee}) > 0$, $C = \text{\_gasPriceCoeffPer1000()} > 0$, $K = \text{\_extraGas()} \ge 0$, and $g_{\text{used}}$ uses configured `callbackGasLimit` upper bound (no clamping `< 100k` up to `100k`). All inputs and intermediate/output values enforce $[0, 2^{256}-1]$ bounds (`_require_uint256`).
- **Distinct Role of `_maxChargeGas`:**
  - Limits gas allocated for payment-settlement execution inside `CallbackProxy` (`pay()` / debit), **NOT** callback execution billing.
  - `_maxChargeGas` is excluded from `estimated_single_callback_fee_wei` and `recommended_min_reserve_wei`.
  - Evaluated strictly against settlement gas adequacy: `_maxChargeGas == 0` -> `RETRY_BLOCKED`; if operator supplies `--settlement-gas-requirement`, `_maxChargeGas < req` -> `RETRY_BLOCKED`, `>= req` -> allowed (`AT_REQUIREMENT` / `ABOVE_REQUIREMENT`); otherwise flagged in `unsafe_or_unverified_conditions` and `missing_or_unavailable_evidence` as `UNVERIFIED_REQUIREMENT`. Missing `_maxChargeGas` fails closed as `RETRY_UNKNOWN`.
- **Configured Gas Limit vs Effective Forwarded Gas:** Reports `effective_forwarded_gas_exact: None` and warns that proxy `_extraGas` and settlement/wrapper overhead make destination gas actually forwarded to `CrossGuardCallback` strictly less than `callbackGasLimit`.
- **Separated Payment Paths:**
  - **`destination_callback_delivery_path` (Unichain Callback Proxy, `ETH`):** `proxy_debt > 0` or `proxy_reserves < recommended_min_reserve_wei` -> hard **`RETRY_BLOCKED`** on both `DISPATCH_REQUIRED` and `RETRY_ELIGIBLE`.
  - **`reactive_event_processing_path` (Reactive System Contract, `REACT`):** `system_debt > 0` or `system_reserves < recommended_min_reserve_wei` suspends/threatens automated RVM `react()` execution, **not** owner EOA transaction signing for manual `dispatchPendingCallback()` / `retryFailedCallback()`. Emits explicit `REACTIVE_PATH_WARNING` in `warnings` & `unsafe_or_unverified_conditions` by default; blocks as `RETRY_BLOCKED` only when `--require-reactive-reserves` (`require_reactive_reserves=True`) conservative whole-pipeline policy is requested. *(Explicitly documented as a conservative safeguard because offline mocks do not verify whether live `SystemContract.requestCallbackV_1_0` checks contract debt).*

Exact live `SystemContract` / `CallbackProxy` ABI getters (`_gasPriceCoeffPer1000`, `_extraGas`, `_maxChargeGas`, `getCallbacks`, `CallbackRequest` logs) and whether live `SystemContract.requestCallbackV_1_0` restricts indebted contracts remain unverified against live RPC nodes.
2. **Unverified Proxy Settlement Cost & Forwarded Gas:** Preflight cannot statically determine exact forwarded gas after proxy overhead (`effective_forwarded_gas_exact = None`) or exact callback settlement gas unless `--settlement-gas-requirement` is supplied by operator testing.
3. **6-Field `getCallbacks` Schema Limit:** Because `getCallbacks(uint256)` does not carry recipient address or origin nonce, preflight depends on 1-to-1 correlation with Reactive transaction receipt `CallbackRequest` logs and fails closed on multi-record ambiguity.
4. **Prototype Scope:** `TestValuationSource` remains an owner-controlled MVP oracle rather than a live decentralized oracle feed, and `CollateralVault` tracks single collateral/debt per position.
